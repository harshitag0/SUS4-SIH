# Project: AgriLink — Perishable Mango (Alphonso) FPO Platform, India → Singapore

## Goal
A trade-and-trust platform linking FPOs/farmers with overseas buyers for perishable Alphonso mangoes. Focus: **consistency, quality, reliability**. Alphonso first, then other perishables.

## Source of truth
- `docs/FLOW.md` — lifecycle, bond state machine, pillars
- `docs/ARCHITECTURE.md` — stack decision and how to add modules
- `docs/BUSINESS.md`, `docs/ROADMAP.md`, `README.md` (run + layout)

## Stack
- `client/` React 18 + Vite + React Router. Farmer UI is multilingual (en/hi/mr in `src/i18n/*.json`), large-text, bottom nav. Buyer UI is English.
- `server/` Node + Express + Mongoose (MongoDB). Modules in `src/modules/<name>/routes.js` exporting `(deps) => ({path, router})`, registered in `src/modules/index.js`. ML client injected via `deps.ml` (fake in tests).
- `services/ml/` Python FastAPI: `app/modules/{forecast,grading,alerts}`. Dummy APEDA/APMC-shaped data in `app/data.py`.
- `docs/modules/` specs for modules not built yet (chatbot, logistics) and status of partial ones.

## Realtime + live data
- Socket.IO shares the API port; `notifier` saves notifications in MongoDB and pushes them (`notification`, `data:changed`). Client: `context/RealtimeContext.jsx`, `useApi(path, { live: ["requirements"] })`.
- Live: weather (Open-Meteo, `server/src/lib/weather.js`), platform demand (`/api/market/live`), mandi prices when `DATA_GOV_IN_API_KEY` is set. Sample: export history + season price forecast (`services/ml/app/data.py`).
- Each browser tab keeps its own login (sessionStorage), so farmer and buyer can be open side by side.

## Supply–Demand engine
- `services/ml/app/modules/supply_demand/`: `model.py` (training, validation, artifact), `service.py` (outlook, markets, recommend), `router.py`.
- Data: `services/ml/data/*.csv` (sample, generated by `scripts/make_sample_data.py`); artifact `services/ml/models/supply_demand.joblib` (auto-trained on first start, `POST /supply-demand/train` to retrain).
- API: `/api/market/outlook`, `/api/market/markets`, `/api/farmers/me/supply-demand`. Client: `pages/farmer/Demand.jsx`.

## Price (cost) prediction engine
- `services/ml/app/modules/price/`: `model.py` (training on `data/prices_weekly.csv`), `service.py` (outlook with demand scenario, `evaluate_offers`, cost constants), `router.py`. Uses the supply-demand outlook for next season's supply growth and demand gap.
- API: `/api/market/price?grade&district&demand_change_pct`; `/api/requirements` returns `advice` per offer for the farmer's district. Client: `pages/farmer/Price.jsx`, `components/OfferAdvice.jsx`.

## Cost & Profit engine + Check before you sign
- `services/ml/app/modules/cost/`: `model.py` (per-component regression on `data/costs_yearly.csv`), `service.py` (`analysis`: year table, farm cost, channels, what-if, benchmark), `router.py`.
- API: `GET/PUT /api/farmers/me/costs` (analysis; save actual costs). `GET /api/bonds/precheck`, `GET /api/bonds/:id/precheck` (`server/src/modules/bonds/precheck.js`).
- Client: `pages/farmer/Profit.jsx`, `components/PreSignCheck.jsx` (in the Offers commit dialog and on unsigned farmer agreements).

## Digital agreements (AgriLink Trust)
- `blockchain/` Hardhat project: `contracts/AgreementRegistry.sol` (OpenZeppelin, append-only hash registry), tests, deploy script → `deployments/<network>.json`.
- `server/src/modules/contracts/`: lifecycle service, ethers chain client, pdfkit PDF, write-once store, hash-chained audit, e-sign providers. Bond creation auto-creates a draft agreement; registration makes the bond binding.
- `client/src/pages/contracts/` + `components/trust/` (navy theme, `trust.css`), routes under `/contracts`. See `docs/BLOCKCHAIN.md`.

## One platform (Module 1 + Module 2)
- Module 2 (teammate's, `module2/`): FastAPI on port 8100 (DB `agrilink_m2`); its React module is imported via Vite alias `@module2` and rendered INSIDE each portal (`client/src/pages/m2/FarmOps.jsx`, `m2-theme.css`): `/farmer/ops/*`, `/buyer/ops/*`, `/ops/farm/*`. The sidebar lists Module 2 pages via `m2NavFor(role)`. Only change to Module 2 source: optional `getHeaders` prop on `M2Provider`.
- One sign-in: the browser calls `/api/m2/*` on the AgriLink API; `server/src/modules/module2/gateway.js` verifies the JWT, drops browser `X-M2-*` headers and sets identity server-side (farmer `AGL-F-<id>`, buyer `AGL-B-<id>`, operations = their chosen desk `m2Role/m2Actor`, `PUT /api/ops/me`).
- Roles: farmer, buyer, operations (demo `9000000001`, read-only on agreements).
- AI Decision Center: `server/src/modules/journey/` (`GET /api/journey`, `/api/journey/:agreementId`). All sources (3 ML engines, weather, capacity, chain, Module 2) run concurrently; 13 stages in order with decision + next action per role; client `pages/Decisions.jsx`.
- Handoff on registration: `server/src/modules/module2/handoff.js` (injectable as `contractDeps.handoff`). Payment terms 50/50 match Module 2 escrow tranches. See `docs/MODULE2.md`.

## Photo grading (vision)
- `services/ml/app/modules/vision/`: `analyze.py` (OpenCV: photo-quality gate, fruit mask, colour score, blemish %, features), `gallery.py` (doctor-graded reference photos, k-NN comparison, logistic-regression grader once 20+ photos), `service.py` (multi-photo result in Module 2's CV contract), `router.py` (`POST /vision/analyze`, `POST /vision/gallery`, `GET /vision/status`). Gallery lives in `services/ml/models/` (runtime, not committed).
- Module 2 uses it when `M2_CV_URL` is set (`module2/backend/app/adapters/cv.py`); doctor visits label the latest photos (`services/quality._teach_gallery`). AI grade is always provisional. Size is not measured from photos (weight at packhouse).
- Tests use generated images (`services/ml/tests/mango_images.py`): behaviour only, not accuracy on real fruit. Thresholds need calibration on real doctor-graded photos.

## Quality certification
- One certificate per collected lot: `server/src/modules/certificates/` (eligibility from Module 2 evidence, PDF + QR, write-once store, hash on `AgreementRegistry` under the certificate id, revocation = version 2). Public pages `/verify/:id`, `/trace/:lotId`. See `docs/CERTIFICATION.md`.

## Stage-wise crop quality assessment
- `server/src/modules/stages/` (config, assess, model, service, routes): crop records, stage submissions with photos, provisional AI+rules report, farmer-doctor review (approve / reject / requires correction), approval issues a stage certificate via `certificates/service.issueStageCertificate` (`kind: "stage"`). Client `pages/stages/`. ML `POST /vision/photo-quality`. See `docs/STAGES.md`.

## Farmer advisory
- `server/src/modules/advisory/` (knowledge, engine, localize, service, routes) + `jobs/advisory.js`: personalised, evidence-based recommendations in en/hi/mr with dates and follow-up; client `pages/advisory/`. See `docs/ADVISORY.md`.

## Advisory lifecycle + messaging
- Lifecycle, agronomist approval/verification, inspection comparison: `server/src/modules/advisory/service.js`, `routes.js`; 7 languages in `knowledge.js` + `knowledge_more.js`.
- WhatsApp / SMS / voice: `server/src/modules/messaging/` (templates, providers, service with logs/retries/webhooks, bridge from in-app notifications and Module 2 messages). Credentials only via env (`server/.env.example`); without them messages are logged as `simulated`.
- Client: farmer `/farmer/advice`, `/farmer/advice/:id`, `/farmer/messages`; agronomist `/ops/agronomist…`; log `/ops/messages`; offline outbox `client/src/offline.js` + `public/sw.js`. See `docs/NOTIFICATIONS.md`.

## Conventions
- Server returns codes, not sentences (alert codes, tip keys, error codes); the client translates them.
- Farmer capacity = expected Grade A tons − tons already in bonds; enforced on bond creation.
- Bond signatures: SHA-256 over canonical terms + side + timestamp + other side's hash (`server/src/modules/bonds/signing.js`).
- Demo OTP is `1234` (`DEV_OTP`).
